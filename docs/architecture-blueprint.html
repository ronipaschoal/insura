Architecture blueprint

Insura — runtime dependency graph

Traced from lib/ itself — actual imports, the get_it registration order in injector.dart, and the widget tree — not from CLAUDE.md or the README. Two shortcuts the running code took, flagged in the first pass of this blueprint, were since fixed in code — see the changelog below.

Pattern: MVVM (View / Cubit / Repository) DI: get_it, interface-first Backend: Firebase Auth + Firestore only — no REST Traced: 2026-09-17

Changelog — divergences fixed

01 · Resolved — DI coverage was incomplete

CLAUDE.md says get_it is "the service locator for repositories, data sources, and cubits," but WebviewCubit was built directly (WebviewCubit()) inside WebviewPage.initState(), outside the DI graph. Fixed: injector.dart now has registerFactory<WebviewCubit>(), and WebviewPage reads it via getIt<WebviewCubit>() — same pattern as every other cubit.

02 · Resolved — router talked to the domain layer directly

app_router.dart's redirect callback and refreshListenable used to call getIt<AuthRepository>() straight from the routing layer, skipping the ViewModel layer entirely. Fixed: a new app-wide AuthCubit (registered as a lazySingleton, since AppRouter.router is one static field for the whole app) now sits between them — AppRouter reads getIt<AuthCubit>().isLoggedIn, and AuthCubit is the one place left that depends on AuthRepository for session state.
